# Модули и контракты

Каждый пример предполагает уже созданные определения и `ResourceStore`. Вызовы идут в главном потоке. Указанные компоненты — необязательные оболочки над тем же API.

## Производство, расход и доставка

```csharp
using EasyResources.Production;

var queue = new ProductionQueue(input, output, capacity: 8, ownerId: "forge-1");
queue.TryEnqueue(recipe, now, out var ticket, quantity: 3);
queue.Tick(now, maximumCompletions: 4);
queue.Pause(now);
queue.Resume(later);
ticket.Cancel();
```

**Recipe** задаёт вход, выход и длительность в миллисекундах. Количество заказа умножает стоимость, результат и время. `Prepare()` замораживает рецепт; подготовленный план можно переиспользовать. Вход резервируется при постановке, выход выдаётся вместе со списанием. Переполненный выход оставляет головной заказ и оплату на месте; `LastFailure` объясняет отказ. Последующие заказы ждут. После освобождения склада следующий заказ начинает отсчёт от текущего времени.

Обычный пропуск времени догоняет последовательные завершения до `maximumCompletions`. Очередь не создаёт Update сама; **Production Station** делает это в unscaled time и использует контейнер на том же объекте как Input, если ссылка не задана. Выключение Station по умолчанию приостанавливает вызовы Tick, сохраняя время и заказы; для явной остановки времени вызовите Pause. Уничтожение отменяет незавершённые оплаты. У компонента есть CaptureState / RestoreState с его часами: сначала восстановите Resource Container с заменой активных резервов, затем Station. Прежний объект Queue заменяется; обновите сохранённые ссылки на него.

Сохраняйте `queue.CaptureState(now)` вместе с `input.CaptureState(true, now)` и выходным хранилищем. После восстановления кошельков используйте `ProductionQueue.FromState(..., nowMilliseconds, capacity, offlineMilliseconds)`. Офлайн-время по умолчанию 0; передавайте доверенное прошедшее время явно. Для приостановленной очереди оно не ускоряет заказ. Сохранённые цены и результаты заморожены: изменение Recipe не меняет уже оплаченную очередь.

```csharp
var generator = new ResourceFlow(store,
    ResourceRate.FromQuantity(fuel, -0.25m),
    new ResourceRate(energy, 10));
generator.Tick(elapsedMilliseconds);
```

Один знаковый rate на ресурс. Остатки дробления времени сохраняются точно; невозможно произвести выход без доступного топлива на этом шаге. Неуспешный шаг не меняет ни ресурсы, ни остатки. Если нужна копящаяся задолженность за пропущенные шаги, храните её в своём планировщике: ResourceFlow её автоматически не создаёт. `CaptureState`/`RestoreState` сохраняют остатки, **Resource Producer** вызывает Tick автоматически.

```csharp
ResourceDelivery.TryStart(origin, destination, cargo, "shipment-42",
    now, travelMilliseconds: 5000, out var delivery, out var failure);
delivery.TryArrive(now, out failure);
```

Доставка удерживает груз у отправителя; это резервирование отгрузки, а не отдельная физическая сущность транспорта. При прибытии выполняется атомарный перевод. Отмена освобождает груз. Движение, потерю транспорта и боевые эффекты определяет игра. `CaptureState` и `FromState` связывают доставку с восстановленным резервом. Зарезервированный для модулей платёж не изменяйте извне: уменьшенная вручную оплата отклоняется при завершении.

## Магазин и кредит

```csharp
using EasyResources.Trading;
var shop = new ResourceShop(catalog, till, stock, taxOffice, broker);
var quote = shop.QuoteBuy(wood, bundles: 2,
    new TradeTerms(priceNumerator: 9, priceDenominator: 10,
                   taxBasisPoints: 1000, feeBasisPoints: 100));
shop.TryExecute(customer, quote, out var failure);
```

**Trade Catalog** содержит размер пачки и цены покупки/продажи. `stock: null` явно означает бесконечного поставщика; касса всегда настоящая, поэтому выкуп ограничен её средствами. Отсутствующие получатели налога/комиссии означают кассу. 100 базисных пунктов = 1%. Покупка округляется вверх, выкуп вниз; налог и комиссия вверх. Вычеты, превышающие выручку, отклоняются при создании котировки. При продаже `TotalPrice` — чистая выручка клиента.

`SetPrice` меняет цену и ревизию, старые котировки отклоняются. Формулу спроса, региональные коэффициенты и изменение курса игра вызывает через SetPrice / TradeTerms; библиотека не навязывает модель рынка. Котировки можно переиспользовать, пока их ревизия действительна. `TryBuy`/`TrySell` — короткие вызовы, создающие котировку; для частого цикла используйте Quote + TryExecute. `CaptureState` сохраняет текущие цены.

```csharp
var credit = new ResourceCreditAccount(bank, wallet, gold, creditLimit: 1000);
credit.TryBorrow(200, out var failure);
credit.AccrueInterest(basisPoints: 500); // Явный расчёт за выбранный игрой период
credit.TryRepay(100, out failure);
```

Долг хранится отдельно. Баланс не уходит в минус, заём не выдаётся автоматически. Проценты могут увеличить долг сверх лимита: это запрещает новый заём, но не удаляет задолженность. Деньги и изменение долга публикуются согласованно. Сохраняйте CreditState вместе с соответствующими кошельками.

## Предметы

```csharp
using EasyResources.Inventory;
var inventory = new InventoryStore(capacity: 24, maximumWeight: 100);
inventory.TryAdd(item, 10, out var failure);
long accepted = inventory.AddUpTo(item, 100);
inventory.TryCraft(wallet, recipeCost, sword, 1, out failure,
    new ItemProperties(quality: 2, durability: 80));
inventory.TryTransferTo(chest, slotIndex: 0, count: 1, out failure);
```

**Item** задаёт максимальный стак, вес, объём, уникальность и максимальную прочность. Ненулевая прочность автоматически требует отдельного экземпляра со стаком 1. Только одинаковые item asset, качество, прочность и точный срок годности складываются вместе. Перевод сохраняет InstanceId; создание выдаёт новый. `TryChangeCondition` меняет состояние экземпляра/стака, `RemoveExpired(now)` явно удаляет испорченное. Нулевой durability сам по себе не уничтожает предмет: правило поломки принадлежит игре.

`TryCraft` и `TryReceiveReserved` не списывают оплату при отсутствии места. `TryResize` сохраняет индексы и отказывает, если сокращение удалило бы занятый слот. Снимок сохраняет точные слоты, ID экземпляров, состояние и оставшийся срок. `RestoreState(..., offlineMilliseconds)` по умолчанию не считает офлайн-время. При загрузке целого мира вызовите `ValidateUniqueItems(inventories)` для обнаружения одного экземпляра сразу в нескольких инвентарях. Глобального статического реестра предметов нет.

## Прогрессия

```csharp
using EasyResources.Progression;
var profile = new ProgressionProfile(definition, wallet);
profile.AddExperience(50, out var failure);
profile.TryUnlock(node, out failure);
profile.TryStartResearch(researchNode, now, "research-42", out failure);
profile.TryCompleteResearch(now, out failure);
decimal speed = profile.GetStat("speed", baseValue: 5);
profile.TryPrestige(new PrestigeRule(minimumLevel: 10, reward: reward), out failure);
```

**Progression Definition** задаёт суммарные XP-пороги уровней 2, 3 и далее и набор узлов. **Node** задаёт ранги со стоимостью и модификаторами, минимальный уровень, зависимости и группу взаимоисключения. Проверяются отсутствующие зависимости и циклы. Ранги независимы у каждого профиля; настройки фиксируются при его создании.

Формула характеристики: `(base + сумма Add всех купленных рангов) × (1 + сумма PercentBasisPoints / 10000)`. Это данные: применение к движению, урону или производству остаётся у потребителя. Профиль ведёт одно активное исследование, удерживая оплату. При отмене резерв освобождается. Для параллельных исследовательских станций создавайте отдельные профили/очереди в игровой модели.

Престиж проверяет уровень и оплату, выдаёт награду и одновременно сбрасывает XP и непостоянные ранги. Узлы **Keep On Prestige** сохраняются вместе со счётчиком PrestigeCount. Активное исследование сначала завершите или отмените. `CaptureState`/`FromState` сохраняют ранги и возобновляют исследование после восстановления кошелька. У **Progression Component** есть CaptureState / RestoreState: восстановите кошелёк первым, затем компонент; новый Profile заменяет прежний, поэтому внешние ссылки и C#-подписки на старый профиль нужно обновить. Сохранявшийся узел может намеренно пережить свой прежний уровень и зависимости при престиже.

## Сетевая авторитетность

```csharp
using EasyResources.Networking;
var authority = new ResourceAuthority(definitions, replayCapacity: 64);
authority.RegisterStore("player-wallet", wallet, ownerId: authenticatedPlayerId);
string session = authority.OpenSession(authenticatedPlayerId);
// Execute получает actor ID от аутентифицированного транспорта, никогда из клиентского DTO.
ResourceCommandResult result = authority.Execute(authenticatedPlayerId, receivedCommand);
```

Встроены Spend и Transfer. Команда содержит session ID, последовательный номер с 1, ожидаемые ревизии, ключи хранилищ, resource ID и положительное количество. Чужой исходный кошелёк запрещён. Входящий перевод в чужой кошелёк разрешается только флагом `acceptIncomingTransfers`. Встроенной клиентской команды выдачи ресурсов нет. Серверные покупки и рецепты регистрируйте через `RegisterAction`: правило добавляет доверенные цены/выдачи в переданный ResourceTransaction и возвращает причину отказа. Оно не должно самостоятельно выполнять побочные операции.

Повтор того же номера с тем же содержимым возвращает кэшированный результат, изменённое содержимое отклоняется. После вытеснения из ограниченного кэша номер остаётся использованным и никогда не применяется заново. Бизнес-отказ тоже расходует последовательный номер; неверная сессия и разрыв последовательности — нет. После reconnect вызывается OpenSession: старая сессия недействительна. Размер кэша и максимум сессий ограничены настройками.

`ResourceAuthority.CaptureState` захватывает все зарегистрированные кошельки и номера обработанных команд вместе. Сохраняйте **весь** снимок одной атомарной записью. RestoreState заменяет их согласованно. После загрузки ответы из старого кэша уже недоступны, но выполненные номера отклоняются; клиент запрашивает свежий снимок. Отдельное сохранение только денег не даёт гарантии от повтора после аварии.

```csharp
var sender = new ResourceReplicator(authoritativeStore, retainedChanges: 256);
var client = new ResourceReplica(definitions);
client.TryApply(sender.Capture(), out var failure);
ResourcePacket delta = sender.Capture(client.StreamId, client.Store.Revision);
client.TryApply(delta, out failure);
```

Клиентский ResourceStore разрешает чтение и события, отклоняет выдачу, оплату и резервирование. Дельты содержат конечные total/reserved и ревизию, нулевые остатки включаются. Если журнал уже потерял нужную ревизию, автоматически отправляется полный снимок. Пропуск/перестановка дельт требует полного снимка; другой stream требует новой ResourceReplica. Принимайте пакеты только от доверенного сервера. Это защита логики команд, не реализация транспорта, шифрования или защиты клиентского процесса. Сериализатор транспорта должен сохранять все 64 бита количества и ревизии: JavaScript Number и float/double для этого недостаточны; для JS-клиента используйте строковое представление Int64 или подходящий бинарный формат.

## Очень большие числа, UI, очереди

`BigResourceStore` использует точный BigInteger в тех же наименьших единицах ResourceDefinition. Есть составная стоимость, обмен, перевод, именованный резерв, JSON-совместимые строки количества и атомарные `TryImport`/`TryExport` в обычный кошелёк. Ограничение количества задаётся `maximums: BigResourceCost`; отсутствующий ресурс не ограничен, явный 0 запрещает запас. Это отдельная экономика для огромных чисел, не замена всех модулей обычного кошелька. Операции BigInteger и подготовка изменяемого состояния выделяют память; этот компромисс явный.

**Resource Panel** можно добавить на объект с Resource Container или вызвать `panel.Bind(store)`, в том числе с `replica.Store`. UIDocument и настройки панели создаются при необходимости. `PreviewCost(cost)` включает проверку доступности. Событие помечает панель изменённой: несколько операций в одном кадре дают одно обновление текста в LateUpdate. Неизменившаяся панель не перечитывает остатки; форматирование при обновлении UI выделяет строки. Bind переключает источник и очищает строки предыдущего кошелька. Существующий UIDocument / PanelSettings сохраняются. Для своего дизайна используйте классы USS `easy-resources`, `easy-resources-row`, `easy-resources-title`, `easy-resources-capacity`, `easy-resources-status` либо собственный подписчик Changed.

`ResourceBatch(capacity)` принимает подготовленные планы через TryEnqueue. Обрабатывайте `Process(maximumOperations, failures)` в удобной точке кадра. Ёмкость фиксирована; заполнение возвращает false. План принадлежит очереди до обработки, изменять его нельзя. Бюджет измеряется количеством полных операций, не миллисекундами и не количеством ресурсов; дорогую единичную транзакцию заранее ограничивайте на уровне игры.
