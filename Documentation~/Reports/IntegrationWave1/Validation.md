# Integration Wave 1 — 12 ноября 2026

Проверена интеграционная граница оплаты EasyResources на Unity **6000.3.22f1**. Версия пакета остаётся **0.2.0**. Core не получил зависимости от других Easy-пакетов. Боевой адаптер и его игровые проверки принадлежат EasyCombat.

## Публичное API

- `ResourceStore.DeferNotifications(context = default)` возвращает `ResourceNotificationScope`: readonly struct, `IsActive`, идемпотентный `Dispose` для всех копий.
- `ResourceReservation.TryCommit(out ResourceFailure)` подтверждает весь оставшийся резерв. Частичный overload и прежний `Commit()` сохранены.
- `ResourceStore.TryGetReservation(id, ownerId, out reservation)` проверяет точное совпадение владельца. Прежний overload без владельца сохранён.

Остатки и резервы внутри области меняются сразу. После закрытия последней области публикуется одно итоговое изменение с одной ревизией и контекстом внешней области. Новая полностью отменённая оплата не оставляет события/ревизии/истории. Область не откатывает игровой мир и не переносится через кадр/await. Снимок и сетевой пакет требуют завершённой границы; явное восстановление инвалидирует старые handles. Полные рецепты: [IntegrationWave1.md](../../IntegrationWave1.md).

## Производительность

Windows x64 Development Player, **Mono**, Intel Core i7-14700KF. Сборка завершена без ошибок и предупреждений; [build-summary.json](build-summary.json). Player завершился с кодом 0.

Каждый сценарий предварительно выполняется 128 раз, затем измеряются 15 пакетов по 1000 полных итераций. Таблица показывает время **1000 итераций**, не одного вызова. Значение p95 — ближайший верхний ранг для 15 измерений. GC учитывает только измеряемый участок текущего потока; положительная калибровка с `new byte[1024]` зарегистрировала одно выделение. Все итоговые балансы/резервы проверены.

| Сценарий | Медиана, мс / 1000 | p95, мс / 1000 | GC.Alloc событий |
|---|---:|---:|---:|
| Прежнее немедленное списание + возврат двух ресурсов | 1.6077 | 1.6473 | 0 |
| Вложенные admission + pulse, commit обоих, возврат | 4.4508 | 4.7989 | 0 |
| Резерв + отмена без событий | 1.6201 | 1.6728 | 0 |
| Перенос двух ресурсов между хранилищами и обратно | 10.7492 | 11.4282 | 0 |

Подробные результаты: [Player](notifications-player.json), [Editor](notifications-editor.json). В Editor те же четыре сценария также дали ноль событий выделения памяти после прогрева. Измерения относятся к переиспользуемым стоимостям/планам и прогретой вместимости коллекций; создание конфигурации, расширение вместимости, сохранения и форматирование UI сюда не входят. Этот прогон не измеряет IL2CPP и полную игровую сцену.

## Воспроизведение

1. Установить пакет из `package.json`, добавить его в `testables` и установить Unity Test Framework. В Test Runner запустить `EasyResources.Tests.EditMode` (118), затем PlayMode-сборки `EasyResources.Tests.PlayMode` (9) и `EasyResources.Tests.UI` (1, при установленном стандартном модуле UI Toolkit). Для Unity Pipeline через HTTP PlayMode запускается с `--async-tests true`; результат читается через `test status`.
2. Для первого запуска импортировать Basics через Package Manager и открыть `Assets/Samples/EasyResources/0.2.0/Basics/ResourceBasics.unity`. Ожидается 13 PASS.
3. Локальные профилировочные компонент и сцена находятся в `Assets/PackageTests/EasyResources/IntegrationWave1`. Проверенная копия также сохранена в указанном чистом проекте. Компонент работает автоматически, без игрового ввода.
4. Собрать только `ResourceNotificationBenchmark.unity` для StandaloneWindows64 с Development и DetailedBuildReport. Запустить Player с `-resourceNotificationReport "<полный путь к JSON>"`. Ожидается четыре строки, `invariantsPassed=true`, `allocationEvents=0`, непустая положительная калибровка, пустая `error`, код выхода 0.

Общие игровые проверки Combat/Building/UI и итоговую EasySuite сцену ведёт координатор; этот отчёт удостоверяет ресурсное ядро и его самостоятельную установку.
